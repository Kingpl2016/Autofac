# 录制与回放说明

本文说明 Art-Net Studio 的节目录制（`.artrec`）与回放实现：数据流、文件与目录布局、过滤语义、回放语义、崩溃恢复、容量上限，以及与核心板固件互通时需要核对的事项。格式本身以《ArtRec 灯光节目录制文件规范》为准，本文只记录实现取舍。

## 1. 总览

```
socket 接收(打单调时间戳) → 接收循环 ─┬→ 信号引擎合并 → 实时显示 / 转发
                                      └→ 录制通道(try_send, 满则丢帧计数)
                                            → RecordFilter 过滤(IP / Universe / 协议)
                                            → 录制专用 SignalEngine 合并
                                            → 变更检测 → ArtRecWriter → .artrec.part + 索引日志

.artrec → 流式 Reader → Player(绝对时间调度 / 倍速 / 循环 / seek / 保活)
        → Dispatcher(转发表或指定 IP)→ UDP
        → player:state / player:channels 事件 → 传输条 / 通道栅格 / 时间线 / 曲线
```

| 模块 | 位置 | 职责 |
|---|---|---|
| `artrec-core` | `src-tauri/crates/artrec-core` | 格式编解码（权威实现），容量上限显式报错，流式 Reader |
| `recorder` | `src-tauri/crates/recorder` | 过滤、变更检测、编码策略、会话、崩溃安全落盘、sidecar、节目库 |
| `player` | `src-tauri/crates/player` | 回放状态机、时间线概览、通道曲线（纯逻辑，虚拟时间可测） |
| `recording.rs` / `playback.rs` | `src-tauri/src` | 录制线程、回放任务、事件推送 |
| `dispatch.rs` | `src-tauri/src` | 实时转发与回放共用的"路由 + 限速 + 延迟 + 发送" |
| `app_mode` / `sender` | `src-tauri/crates/host-core` | 应用运行模式状态机（实时 / 播放器，切换顺序可测）与发送器健康度 / 自愈 |
| `disk` | `src-tauri/crates/recorder` | 磁盘空间守卫：阈值分级与"等级变化才通知" |
| `features/app-mode` | `src/features/app-mode` | 模式开关、确认对话框、播放器页横幅 / 入口卡片、实时专属页面守卫、退出守卫 |
| `features/recording` | `src/features/recording` | 录制 / 回放双模式页面：录制舱与设置、常驻节目库侧栏（卡片 + 缩略图）、回放传输台、时间线热力图、通道曲线 |

## 2. 存储

### 2.1 格式与默认编码策略

唯一存储格式是 `.artrec`（不引入私有格式，以便直接上传核心板 SD 卡）。默认编码为 **Zstd L3 + 仅全量帧**，依据 `cargo run --release -p recorder --example bench` 的基准（44Hz × 60s，1 / 10 / 50 个 Universe）：

- Zstd 对稀疏 DMX 全量帧压缩极好（静止 50 个 Universe 仅约 2.6 KiB，跑马灯 50 个 Universe 约 157 KiB）。
- 差分帧每个变更点固定 5 字节且几乎不可再压缩，在 Zstd 下从未显著优于全量帧（跑马灯 50 个 Universe 差分约 976 KiB，约大 6 倍）。
- 差分帧是规范里的可选扩展，**不支持的解析器必须拒绝打开**置位了 `ALLOW_DIFF_FRAME` 的文件，固件是否支持尚未确认。

因此默认不写差分帧，文件头 `flags` 为 0；每个变更帧天然是关键帧，seek 无需回溯。差分模式仍保留（`EncoderConfig::allow_diff`），Reader / Player 完整支持。

写帧采用**变更触发**（规范 §8.2 推荐）：录制线程以约 45Hz 的节拍检查合并结果，数据无变化则不写帧；结束时补一个收尾帧，使最后一帧索引的 `time_us` 等于 `total_duration_us`（规范 §8.3）。

### 2.2 目录与文件

录制目录取自设置（`recording.directory`），为空时用文档目录下的 `ArtNet Studio Recordings`。

| 文件 | 说明 |
|---|---|
| `名称.artrec` | 节目本体，严格遵循规范，可直接上传核心板 |
| `名称.artrec.json` | sidecar：名称、备注、过滤条件、来源设备、协议、时长、帧数、大小、是否恢复生成、时间线概览缓存。缺失时节目库仍能仅凭 `.artrec` 列出 |
| `名称.artrec.part` | 录制进行中的临时文件 |
| `名称.artrec.idx` | 录制进行中的索引日志（每帧 16 字节，与 `.artrec` 内索引条目同格式） |

文件名由前端按本地时间生成（`yyyyMMdd-HHmmss_名称`），后端规整非法字符、避开 Windows 保留名并在重名时追加 `-2`、`-3`。

### 2.3 崩溃安全

1. 录制期间写 `.part`，每写出一帧同步追加 16 字节索引日志。
2. 每秒一次检查点：先 `flush + sync_data` `.part`，再刷日志，因此日志里出现的条目对应的 Chunk 一定已落盘。
3. 正常停止：补收尾帧 → 写索引表 → 回填头部 → `sync_all` → 原子重命名为 `.artrec` → 写 sidecar → 删除日志。
4. 异常退出：下次启动（任何新录制开始之前）扫描孤立的 `.part`，取日志中"连续、时间非降、Chunk 头一致"的最长前缀，截掉未确认的尾部，补索引与头部后重命名；无有效帧则清理；无法解析则改名为 `.part.bad` 隔离。恢复出的节目带"已恢复"标记，界面在启动时提示。

最多丢失最近约 1 秒的数据。

### 2.4 自动分段

设置 `recording.splitMinutes > 0` 时，到点后收尾当前文件并立即在同目录开始下一段（`名称-part2`…），Universe 集合保持不变，时间轴各段独立从 0 开始。

## 3. 来源过滤

过滤发生在接收循环旁路之后、合并之前，三类条件取交集，某一类为空表示该维度不限制：

- 来源 IP：白名单，或勾选"排除所选设备"变黑名单。
- Universe 范围：如 `0-3, 10`。
- 协议：Art-Net / sACN。sACN 默认关闭（见设置「启用 sACN」）；关闭时界面不显示协议过滤，录制按“不限制协议”处理，接收循环也会丢弃迟到的 sACN 帧，因此不会写入任何 sACN 数据。

同一 Universe 里被选中的多个来源，按全局合并模式（HTP / LTP / Priority）合并后写入**单轨**。录制不拖慢接收：接收循环只做一次原子读取和非阻塞 `try_send`，通道满则丢弃该帧并在界面显示丢帧数。

**Universe 集合在开始录制时固定**，取"当前活跃且通过过滤的 Universe ∪ 手动指定的 Universe"。录制开始后才出现的 Universe 不写入，计入"被忽略的 Universe"并提示。

## 4. 回放

- **播放器模式**：打开节目即**自动进入播放器模式**（见 §4.2）。它不是"暂停一下实时接收"，而是整体拆除接收任务、释放端口、清空实时状态，只保留发送。录制进行中必须先停止录制（界面有确认，会先停止并保存）；播放器模式下不能开始录制。
- **输出目标**：转发表（与实时信号相同的路由、偏移、延迟），或直接发往指定设备（IP / 协议 / 端口，Universe 编号保持不变）。回放**不经 44Hz 限速**，节奏由文件时间轴决定。倍速 2x 时输出频率可能达到录制频率的 2 倍。
- **保活**：变更触发的录制在静止段没有帧，播放器按 1 秒间隔重发当前全部 Universe（暂停时同样保活），避免节点因长时间无数据而熄灯。1 秒是保守取值，低于常见节点的无数据超时，未对具体设备逐一验证。
- **落后合并**：调度被阻塞落后于时间轴时，多个到期帧合并，只输出最终状态。
- **容错**：帧 CRC / 解压失败时沿用上一帧继续（规范 §11 演出容错模式），并在界面累计显示损坏帧数。
- **倍速 / seek**：倍速 0.25x ~ 2x，播放中无缝切换；seek 立即补发该位置的完整状态；位置早于首帧时无输出。
- **重复模式**：关闭 / 循环 / 连播，三选一，沿用到之后打开的节目（文件头自带的循环标志在用户未显式选择时作为初始值）。
  - 关闭：播完停在结尾，再点播放从头开始。
  - 循环：当前节目播完后回绕，落后多个周期时不逐圈补算。
  - 连播：播完后按**节目库列表顺序向下**（修改时间从新到旧）自动打开并播放下一个，**跳过损坏文件**，到列表末尾停止。下一个打不开时停在当前节目结尾并提示。后端通过 `player:playlist` 事件（`advanced` / `listFinished` / `advanceFailed`）告知前端。

### 4.1 界面与可视化

回放有独立的**播放器页**（`/player`），录制页（`/recording`）只保留录制。节目库在两页都作为右侧常驻侧栏（≥ 1280px），较窄时收进抽屉。

- 录制舱：大号时间码、脉冲指示灯、开始 / 停止主按钮、帧数 / 大小 / Universe 数 / 丢帧 / 剩余空间等实时指标，以及已录 Universe 的活动条（按有输出的通道数缩放）。
- 顶栏录制按钮：任何页面都能开始 / 停止录制（与全局快捷键共用同一实现）；录制中显示停止按钮与时间码，旁边的"录制详情"展开时长 / 帧数 / 丢帧 / 大小 / Universe 数 / 剩余空间。播放器模式下按钮不隐藏，用 `aria-disabled` 保持可聚焦并说明原因。
- 节目库卡片：迷你热力图缩略图（卡片进入可视区后才请求概览，复用后端 sidecar 缓存）、名称、时长 / 帧数 / 大小 / Universe 数，支持搜索、回放、上传、重命名与删除（移入系统回收站）；正在播放的节目高亮，连播时下一个节目带"下一个"标记，切换节目时自动滚入可视区。
- 传输台：播放 / 暂停 / 停止、重复模式（关闭 / 循环 / 连播，快捷键 `L` 依次切换并向读屏播报）、倍速、可拖动的进度滑杆与大号时间码；"关闭节目"只卸载节目，不退出播放器模式。
- 时间线热力图：横轴时间、纵轴 Universe，颜色从冷到暖反映电平与变化强度（附色阶图例）；点击 / 拖动 / 方向键跳转，悬停时在标尺上显示该位置的时间；点击行标签切换通道栅格查看的 Universe。概览由后端扫描一次生成并缓存到 sidecar（文件大小或帧数变化后自动失效）。
- 512 通道栅格：复用实时 Universe 视图的 `ChannelGrid`，数据来自 `player:channels`。
- 通道曲线：选定 Universe 与最多 16 个通道，整段或播放头前后 10 / 60 秒；后端按画布宽度做 min/max 降采样，单帧尖峰不会丢失。
- 信号流：回放期间显示"回放源 → Universe → 目的地"，暂停 / 停止时不带流动动画。

热力图与曲线都提供文字替代（每路 Universe 的活动摘要、每个通道的范围）。

### 4.2 播放器模式

应用有两个运行模式：**实时**（接收、合并、转发、录制）与**播放器**（只播放节目）。顶栏的"实时 | 播放器"分段开关随时切换，它是进入播放模式的常驻入口（侧栏没有独立的播放器页入口）：实时模式下点"播放器"先确认再进入并跳到播放器页，已在播放器模式时再点"播放器"则直接回到播放器页；在节目库里打开节目同样会自动进入播放器模式。

切换顺序集中在 `host-core::app_mode::ModeManager`，通过 `ModeDeps` 注入动作，因此顺序可以用假实现做确定性测试：

| 方向 | 顺序 |
|---|---|
| 进入播放器模式 | 拒绝（录制进行中，`recording_active`）→ 置位模式标志（接收循环立刻丢弃一切实时帧，包括通道里已排队的）→ 拆除 Art-Net 与 sACN 接收任务（端口释放）→ 清空信号引擎 / 设备表 / 限速状态 → 确保发送器就绪 |
| 退出播放器模式 | 关闭节目 → 重建 Art-Net 与 sACN 接收 → 清除模式标志 |

要点与取舍：

- **切换互斥**：切换进行中再次触发立即返回 `transition_in_progress`，不排队。
- **设置保存不会"复活"接收**：播放器模式下 `apply_settings` 不重建 sACN 接收；退出时以最新配置重建。
- **接收重建失败**（例如 6454 被独占）：模式照常切回实时，但状态标为 `failed`，顶栏出现"接收未绑定 + 重试"，重试是对 `app_mode_set("live")` 的幂等调用。
- **扫描**：接收未绑定期间 `scan_network` 返回 `artnet_disabled`。
- **打不开节目不留在空的播放器模式**：`player_open` 在实时模式下先进入播放器模式，节目打不开则退回实时。
- **`player_close` 只卸载节目**，不退出播放器模式。
- **确认规则**：进入播放器模式一律确认（它会让正在转发的实时信号停止）；退出只在**正在播放**时确认。录制中进入会先停止并保存录制。
- **不移植集群与守护**：参考应用里的 cluster player 角色、Guardian 与本工程无关。

#### 发送器自愈

分发器在每次发送后上报成败（`SenderHealth`）。**连续** 5 次失败（中间有成功则重新计数）就判定发送套接字需要重建，由监督任务按 100 / 200 / 400 / 800 / 1600 / 3200 / 5000 毫秒的阶梯反复重建，永不放弃；连续 3 次重建失败状态从"重连中"升级为"不可用"。首次创建发送器走同一条路径。状态通过 `app:mode` 事件的 `sender` 字段（`ready` / `reconnecting` / `down`）告知界面，播放器页横幅显示"输出就绪 / 重连中 / 不可用"。

#### 播放器页（`/player`）

- 播放器模式：常驻横幅（模式说明、输出健康、唯一的"退出播放器模式"入口）+ 回放面板（传输台、时间线热力图、通道曲线、输出目标、512 通道栅格）。
- 实时模式：入口卡片，说明进入后会发生什么，由用户主动进入。
- 走转发表但没有启用的目的地时，输出目标卡片里有持续警告，避免舞台无声变黑。
- 依赖实时信号的页面（Universe 视图、设备发现、录制）在播放器模式下显示说明面板，侧栏里标注"已暂停"；顶栏底边换成强调色，任何页面都能一眼看出当前模式。

#### 退出收尾与启动

- 关闭窗口时若正在录制或播放，后端拦下并通知前端（`app:close-requested`），前端对话框逐条写明后果（录制会先停止并保存；播放会停止输出），确认后调用 `app_quit`：卸载节目 → 停止并保存录制 → 退出。`RunEvent::ExitRequested` 兜底：任何途径触发的退出，只要录制还在就先收尾。
- 设置项 `player.startInPlayerMode`（默认关）：启动即进入播放器模式，给无人值守的节目播放机用。

### 4.3 删除与回收站

节目库删除把节目和它的 `.artrec.json` 在**一次**操作里移入系统回收站，可在回收站恢复。移动失败时文件原样保留并报错，**绝不退化为永久删除**。

## 5. 容量上限

写入端对会溢出的输入显式报错，不做静默截断：

| 限制 | 值 | 原因 |
|---|---|---|
| Universe 编号 | ≤ 2047 | 规范 §4：`net` 0~127、`subuni` 0~15 |
| 单文件 Universe 数 | ≤ 127 | `payload_raw_sz` / `chunk_cmp_len` 为 u16，单帧全量 Payload ≤ 65527 字节 |
| 单文件大小 | < 4 GiB | 偏移字段为 u32，超出请开启自动分段 |

超出范围的 Universe 在录制前的预览里就会提示，并在录制时被忽略。

### 5.1 磁盘空间守卫

录制目录所在卷的剩余空间（十进制 MB / GB）：

| 剩余空间 | 行为 |
|---|---|
| < 500 MB | 拒绝开始录制（`disk_low`）；录制舱禁用开始并就地说明，附"更改录制目录"入口 |
| < 1 GB | 告警（`recording:disk` 事件 + toast），录制继续 |
| < 100 MB | **自动收尾并停止**，文件仍是合法 `.artrec`；`recording:finished` 带 `stoppedBy: "disk"`，录制舱显示不会消失的 `role="alert"` 提示 |

录制期间每 10 秒检查一次，只在等级**变化**时推送事件。查询失败（目录不存在、平台不支持）时不阻止录制。线程自行结束（磁盘告急 / 写盘错误）后无需先调用 `recording_stop`，空间恢复即可直接再次开始。

## 6. 固件互通核对清单

以下按规范文档实现，**尚未用真实固件验证**，固件确认后只需改 `artrec-core` 中集中的位置：

- [ ] 文件头尺寸：规范正文与 §13 示例为 64 字节，而 §3 / §12 的 C 结构体按 `pack(1)` 实际为 88 字节。当前写 64 字节，读取端完全按头部偏移字段定位分区，两种尺寸都能读。
- [ ] Universe 编码：当前 `universe = net * 16 + subuni`（`net = u / 16`，`subuni = u % 16`），入口唯一为 `UniDesc::from_universe`。若固件按 15 位 Port-Address 解析需要同步调整。
- [ ] 物理分区顺序：当前为 A（头）→ B（Universe 表）→ D（Chunk 池）→ C（帧索引），索引在尾部；规范允许任意顺序，但固件若硬编码"C 紧跟 B"则需确认。
- [ ] 是否支持差分帧（决定能否启用差分模式）。
- [ ] 把一个录制样例上传到 SD 卡并用 `esp_program_op` 触发播放，核对节奏与数据。

| `recording_open_dir(path?)` | 在系统文件管理器中打开目录；**只打开目录**，传入文件一律拒绝（`not_a_directory`） |
| `recordings_list` / `recordings_rename` / `recordings_delete` | 节目库（删除移入回收站） |
| `esp_upload_recording(path)` | 后端直接读盘上传到核心板 |
| `app_mode_get` / `app_mode_set(mode)` | 应用运行模式（`live` / `player`）；`app_mode_set` 是 `async` 命令，保证在 Tokio 上下文中重建接收套接字 |
| `app_quit` | 安全退出：卸载节目 → 停止并保存录制 → 退出 |
| `player_open` / `player_play` / `player_pause` / `player_stop` / `player_close` | 回放控制（`player_open` 在实时模式下自动进入播放器模式；`player_close` 只卸载节目） |
| `player_seek` / `player_set_speed` / `player_set_repeat` / `player_set_target` / `player_set_viewed` | 回放参数（`player_set_repeat` 取代了原来的 `player_set_loop`，参数 `mode`：`off` / `loop` / `playlist`；没有节目时也可设置） |
| `player_status` / `player_overview` / `player_series` | 状态、时间线概览、通道曲线 |

事件：`recording:stats`、`recording:finished`（自动停止时带 `stoppedBy`）、`recording:disk`（空间等级变化）、`engine:sources`（约 4Hz）、`player:state`（约 30Hz，非播放时约 2Hz 兜底）、`player:channels`（仅被查看的 Universe，数据有变化才推送）、`player:playlist`（连播结果）、`app:mode`（`{ mode, receivers, sender }`，模式切换或发送器状态变化时推送）、`app:close-requested`（关闭窗口被拦下，`{ recording, playing }`）。

所有接收外部路径的命令都会校验路径必须是录制目录直接子级的 `.artrec`，防止通过 `..` 或绝对路径误删 / 误改目录外的文件。

错误码（`invoke` 的 rejected 字符串）：`already_recording`、`no_universes`、`not_recording`、`disk_low`、`playback_active`、`recording_active`、`transition_in_progress`、`no_player`、`bad_target`、`bad_path`、`already_exists`、`outside_library`、`not_found`、`unknown_universe`、`not_a_directory`、`trash_failed: <原因>`（无法移入回收站，文件原样保留）。

## 8. 设置

`settings.json` 的 `recording` 段（旧版只有 `directory` 的配置可直接加载，缺失字段回落默认值）：

| 字段 | 默认 | 说明 |
|---|---|---|
| `directory` | `""` | 空表示默认目录 |
| `compression` | `zstd` | `zstd` / `none` |
| `zstdLevel` | `3` | 1~9 |
| `splitMinutes` | `0` | 0 表示不分段，最大 1440 |

设置页的录制目录一行提供"浏览…"、"打开目录"、"恢复默认"，输入停顿后检查**草稿值**（保存前就能看到新目录是否可写、剩余多少空间；路径是文件或不可写时就地给出具体错误）。

`player` 段（没有该段的旧配置照常加载）：

| 字段 | 默认 | 说明 |
|---|---|---|
| `startInPlayerMode` | `false` | 启动即进入播放器模式（无人值守的节目播放机用） |

## 9. 验证与已知限制

自动化验证（均已通过）：

- `cargo test --workspace`：格式容量上限与往返、过滤 / 编码 / 会话、崩溃恢复（含日志半条记录、残骸隔离、重名不覆盖）、节目库路径安全、回放调度（虚拟时间）、概览与曲线、分发器 UDP 端到端、录制 50 个 Universe × 44Hz 持续负载不丢帧、真实文件经 UDP 回放。
- 本轮新增覆盖：磁盘阈值与自动停止（含自动停止后可直接再次开始）、目录检查、重复模式三态与连播（自动接续 / 列表末尾停止 / 下一个损坏时停在当前节目）、回收站（节目与 sidecar 同批移动、失败不退化为永久删除）、模式切换顺序与互斥、播放器模式下保存设置不复活 sACN 接收、打开节目自动进入 / 失败回退、发送器连续失败判定与阶梯重建。
- `npm run verify`：类型检查、ESLint、组件与纯函数测试（含模式开关的手动激活与确认流程、顶栏录制按钮、播放器页、退出守卫、设置页目录行与读屏播报）。

未验证 / 已知限制：

- 未接入真实 Art-Net 设备与核心板做端到端联调；未做 1 小时以上的长时间稳定性测试。
- 回放调度使用 Tokio 定时器，Windows 默认系统定时器分辨率约 15.6ms 时帧到达时刻可能有该量级的抖动；如需更高精度可在宿主层提升系统定时器分辨率。
- 退出播放器模式时重新绑定 Art-Net 6454 端口可能失败（例如被其他软件独占）。此时模式照常切回，但接收标为 `failed` 并提示重试；`SO_REUSEADDR` 在 Windows 与类 Unix 上的语义不同，**没有对真实 6454 端口写自动化测试**（避免与开发机上的其他 Art-Net 软件冲突），该路径靠 `ModeManager` 的假依赖测试覆盖顺序与状态，实机重绑需手动验证。
- 发送器自愈的"连续 5 次失败"阈值是经验值：只有所有目的地都失败才会触发，单个不可达目的地不会误触发，但也意味着"只配置了一个目的地且它不可达"时会反复重建（无害，状态会短暂显示重连中）。
- 连播的顺序取决于节目库的排序（修改时间从新到旧）；重命名或复制文件会改变顺序。
- 同一 Universe 的多个来源合并后写单轨，不支持按来源分轨回放。
- 录制期间 Universe 集合固定，不支持中途追加。
