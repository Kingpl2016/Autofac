# 3D 舞台与灯具资源说明

本文说明节目编辑器的 3D 舞台、灯具的外形与 2D / 3D 资源、资源文件的保存位置，以及内存控制的做法。
AI 助手怎样适配灯具见 `AI 助手说明.md` 4.7 节；OFL 导入怎样填外形和物理参数见 `OFL 适配说明.md` 2.6、2.7 节。

## 1. 使用

| 位置 | 操作 |
|---|---|
| 编辑器预览区 → “3D” | 打开 3D 舞台。左键拖动旋转视角、右键拖动平移、滚轮缩放；HUD 上有观众视角 / 俯视 / 侧面三个预设，F 回到观众视角 |
| 3D 舞台 → 单击 / Shift 拖动 | 选灯 / 框选（Ctrl、Shift 加选），Ctrl+A 全选，Esc 取消。选择与编程器、2D 舞台共用 |
| 3D 舞台 → “布置” | 底部出现与 2D 相同的布置工具条。直接拖动灯具或布景物件，在它所在高度的水平面上移动（按“布置吸附”步长吸附，按住 Alt 不吸附）；单击布景物件选中它，Delete 删除。选中的第一台灯上出现手柄：“高度”模式上下拖动（5 cm 一步），“朝向 / 俯仰”模式拖动绿色环改朝向、红色环改俯仰。松开时把变化量应用到全部选中的灯，一步撤销 |
| 3D 舞台 → “场景” | 光束画质（自动 / 高 / 中 / 低）、烟雾浓度、场馆模型（导入、从资源库选、位置 / 角度 / 缩放、移除），见第 5、7 节 |
| 3D 舞台 → 上传按钮 | 为所选第一台灯的型号导入 3D 文件（GLB / glTF / OBJ），见第 4 节 |
| 3D 舞台 → “统计” | 每秒刷新几何体数、纹理数、绘制调用、三角面数与体积光束数 |
| 布置条 → 添加物件 | 桁架、矩形、圆形、多边形、台阶、立柱、LED 屏、文字。多边形可改边数，选中后在 2D 舞台里拖动顶点手柄改形状；台阶可改级数；LED 屏选择内容（视频素材或像素灯） |
| 布置条 → 选中灯具时的“挂到桁架 / 沿桁架均分” | 舞台上有桁架时出现（多个桁架时先选一个）。灯落到桁架中线上，高度取桁架底面，设为吊挂；均分按工程顺序沿桁架等距排开 |
| 灯具库 → 编辑 → 图案通道的能力区间 | 每个图案槽位旁有图案选择：自动（按槽位名匹配）、20 种内置图案，或导入 / 选择资源库里的图案图片（SVG / PNG / WebP） |
| 灯具库 → 编辑 → “像素、物理参数与外观” | 尺寸、重量、功率、镜头、运动方式、外形模板、2D 图标（导入或从资源库选）、3D 模型（从资源库选） |
| 灯具库 → 编辑 → “发光体校准” | 逐个发光体填颜色 / 色温 / 相对亮度；“套用典型 LED”按常见舞台 LED 的近似颜色和白光色温填写，不改相对亮度 |
| 灯具库 → “清理未引用资源” | 把灯具库和打开的节目都没用到的图标、3D 模型、图案图片与场馆模型移到回收站（`data/trash`，30 天） |
| 2D 舞台布置条 / 配接详情 | 俯仰、台高、布景物件的离地高度与厚度 |

## 2. 数据

### 2.1 坐标

舞台坐标单位为米，原点在舞台前沿中央：x 向右（观众视角），y 向后，z 向上，从台面算起。three.js 场景用 Y 向上：`(x, y, z) → (x, z, -y)`，观众在场景的 +Z 一侧。

灯具的本地坐标系（`stage3d/math.ts`）：

- `up`：从底座指向灯头。站立为 +z，吊挂为 -z。Pan 绕它转，Tilt 为 0.5 时光束沿它射出。
- `front`：水平朝向。朝向为 0 时朝观众（-y），正角度转向 +x，与 2D 舞台一致。
- `right = up × front`。几何体的本地 X / Y / Z 依次对应 right / up / front。
- 俯仰 `pitch` 让光轴朝 `front` 倾斜。例如吊挂的面光朝向 180°、俯仰 45°，光束斜着落到台面上。

Pan 增大时光束从朝向转向 +x。吊挂时 `up` 朝下，同样的角度在俯视里反向，与 2D 舞台对吊挂灯用 `1 - pan` 的结果相同。

### 2.2 工程（版本 5）

| 字段 | 说明 |
|---|---|
| `fixtures[].stage.pitch` | 俯仰安装角（度，-90~90）；0 时省略 |
| `stage.height` | 台面高度（米，0~20）；0 时省略。3D 舞台画出台体，台口外的光束落到观众区地面 |
| `stage.objects[].z` | 布景物件底面的离地高度（米） |
| `stage.objects[].height` | 物件自身的竖直厚度（米）；省略时桁架 0.3、平台 0.4、文字 0（`objectHeight`） |
| `fixtureModels[].appearance` / `physical` | 模型快照带外观与新增的物理参数，换电脑打开时不依赖灯具库 |

v4 文件原样升级（`MIGRATIONS[4]` 只升版本号）。Rust 引擎不读这些字段。

### 2.2.1 工程（版本 6）

| 字段 | 说明 |
|---|---|
| `stage.objects[].kind` | 新增 `screen`（LED 屏）、`stairs`（台阶）、`pillar`（立柱）、`polygon`（多边形台面） |
| `stage.objects[].points` | 多边形的顶点（米，相对物件中心、旋转前，3~64 个）；`w` / `h` 是顶点的包围盒 |
| `stage.objects[].steps` | 台阶级数（1~50，省略为 4） |
| `stage.objects[].content` | LED 屏内容：`{ kind: "media", mediaId }`（视频素材）或 `{ kind: "fixture", fixtureId }`（像素灯）；省略时黑屏 |
| `stage.haze` | 烟雾浓度（0~1，省略为 0.35），决定 3D 里光束的可见程度 |
| `stage.venue` | 场馆模型 `{ hash, name, x, y, z, rotation, scale }`（资源库里种类为 venue 的 GLB） |
| `fixtureModels[].properties[].capabilities[].pattern` | 图案槽位投射的图案：`builtin:<名称>` 或图案图片的散列；省略时按槽位名自动匹配 |

各类型的尺寸含义：LED 屏 `w` 为屏宽、`h` 为屏体厚度、`height` 为屏高、`z` 为底边离地高度，旋转 0 时屏面朝观众；台阶 `w` 为宽、`h` 为进深、`height` 为总高，旋转 0 时前低后高；立柱 `w` 为直径。默认高度：LED 屏 3 米（底边离地 0.5 米）、台阶 0.8 米、立柱 4 米、多边形 0.4 米。

v5 文件原样升级（`MIGRATIONS[5]` 只升版本号）。Rust 引擎只校验 `pattern` 的格式（`is_pattern_ref`），不使用它。

### 2.3 灯具模型

| 字段 | 说明 |
|---|---|
| `physical.dimensionsMm` | `[宽, 高, 深]`（毫米），按 OFL 的含义：灯具正常摆放、镜头朝前时的宽、高、深 |
| `physical.weightKg` / `powerW` / `lensName` / `focusType` | 重量、功率、镜头名、运动方式（head / mirror / barrel / fixed） |
| `appearance.shape` | 外形模板：movingHead、scanner、par、wash、profile、bar、pixelPanel、strobe、blinder、fogger、laser、generic |
| `appearance.icon` / `model3d` | 资源引用 `{ hash, format, name }`：图标为 svg / png / webp，3D 模型只能是 glb |
| `appearance.origin` | rule（导入时推断）/ ai（AI 建议、用户确认）/ user（手动） |
| `capabilities[].colorAlt` | 分色片的第二种颜色 |

Rust 与前端各有一份校验（`validate_physical` / `validate_appearance` 与 `validate.ts`）：数值为有限正数，散列是 64 位小写十六进制，格式与种类相符。

## 3. 资源文件的保存位置

```
data/fixture-assets/
  index.json              索引：散列 → 种类、格式、大小、原始文件名、三角面数、包围盒、有无关节、导入时间
  icons/<sha256>.svg|png|webp
  models/<sha256>.glb     3D 文件在前端规整后统一保存为 GLB
  gobos/<sha256>.svg|png|webp   图案图片（灰度投射：亮处透光，透明处遮光）
  venues/<sha256>.glb     场馆模型（规整后的 GLB，上限 64 MiB）
  thumbs/<sha256>.webp    3D 模型的缩略图（文件名是模型的散列）
```

资源的种类由所在目录决定（`AssetKind`：icon / model / gobo / venue），索引重建时按目录识别。

- 文件名就是内容的 SHA-256，同样的内容只存一份。灯具模型和工程里只记散列。
- 只有后端写这个目录（crate `fixture-assets`，命令在 `src-tauri/src/fixture_asset_commands.rs`）。写入前按内容校验：PNG / WebP / GLB 看文件头（GLB 还核对头里的总长度），SVG 必须是含 `<svg` 的 UTF-8 文本，并拒绝脚本、`foreignObject`、实体声明、`javascript:`、事件属性和外部网络引用。
- 大小上限：SVG 1 MiB，PNG / WebP 4 MiB，GLB 16 MiB，缩略图 512 KiB，3D 源文件 256 MiB；资源最多 4096 个。
- 索引丢失或损坏时按磁盘上的文件重建（原始文件名丢失）。
- 前端加载前调用 `fixture_assets_authorize`，它只放行各种类的目录与 `thumbs/` 且不递归，再用 `convertFileSrc` 得到地址。
- 引用统计包括模型外观（图标、3D 模型）、图案槽位的 `pattern` 散列与打开的工程的 `stage.venue`。
- 3D 模型与缩略图经原始二进制 IPC（`tauri::ipc::Request`）传给后端，元数据放在请求头里，不转成 JSON 数组。
- 清理（`fixture_asset_cleanup`）：引用来源是灯具库（后端统计）加上前端登记的引用（`registerAssetReferences`，节目编辑器登记打开的工程）。未引用的文件先挪到 `fixture-assets/.cleanup-<时间>/`，连同一份索引放进回收站。没打开的节目文件里引用的资源也可能被移走，那些节目打开时按外形显示。
- 工程只保存引用，不附带资源文件。换到另一台电脑时缺文件的型号按外形模板显示，3D 舞台右上角提示“N 个型号的 3D 文件不在本机”。

| 命令 | 作用 |
|---|---|
| `fixture_asset_list` | 资源列表（带文件路径） |
| `fixture_asset_import_file(path, kind?)` | 从文件导入图标（默认）或图案图片（`kind: "gobo"`） |
| `fixture_asset_put`（原始二进制，请求头 `x-asset-format`、`x-asset-kind`、`x-asset-name`、`x-asset-stats`） | 存入规整好的 GLB 等；`x-asset-kind` 省略时按格式（图片为图标、GLB 为灯具模型），场馆模型要给 `venue` |
| `fixture_asset_put_thumb`（原始二进制，请求头 `x-asset-hash`） | 保存缩略图 |
| `fixture_assets_authorize` | 放行资源目录 |
| `fixture_asset_source_authorize(path)` | 放行用户选择的 3D 源文件（`.gltf` 连同所在目录，不递归） |
| `fixture_asset_cleanup(referenced)` | 清理未引用资源 |

错误码：`bad_path`、`bad_format`、`too_large`、`unsafe_svg`、`full`、`not_found`、`io`、`bad_request`。

## 4. 3D 文件导入

`stage3d/importModel.ts`，全部在前端完成，GLTFLoader / OBJLoader / GLTFExporter / SimplifyModifier 按需动态导入：

1. 读文件。glTF 的外部 `.bin` 与贴图按同目录的相对路径取；支持 Meshopt 压缩，不支持 Draco。
2. 按“源文件里光束朝向”（上 / 前 / 后 / 下）转到 Y 为光轴。
3. 缩放：型号有尺寸且勾选了“按型号尺寸缩放”时，按最长边等比缩放到型号尺寸；否则按单位猜测（最长边超过 20 视为毫米，超过 5 视为厘米）。底面中心移到原点。
4. 名为 `pan` / `yoke` 与 `tilt` / `head` 的节点作为关节（Tilt 节点要在 Pan 节点下面），Tilt 节点的位置是灯头支点。关节不完整时整灯并成一个灯体。
5. 每个部分合并成一个几何体，只保留位置、法线和顶点色。材质颜色乘进顶点色，贴图与 UV 丢掉。
6. 三角面超过 10 万时按比例简化。
7. 写成规整格式的 GLB（`stage3d/glbFormat.ts`）：`base`、`pan/yoke`、`pan/tilt/head` 三个网格，根节点 extras 里记灯头支点、光束起点、发光面半径。
8. 存进资源库，生成 160 像素的 WebP 缩略图（临时离屏渲染器，用完立即释放上下文），再写进工程的模型快照（一步撤销）和灯具库里的同一模型（内置模型只改工程）。

场馆模型（“场景 → 场馆模型 → 导入”，`normalizeVenue`）用同一套读取流程，规整方式不同：

1. 源文件单位可选自动（最长边超过 3000 视为毫米、超过 400 视为厘米，否则为米）或指定米 / 厘米 / 毫米 / 英寸；Z 向上的源文件（多数 CAD、SketchUp 导出）勾选“Z 轴向上”。
2. 水平居中、底面放在 0；之后在场景设置里调位置（x / y / 高）、角度与缩放。
3. 全部网格合并成一个带顶点色的几何体，超过 30 万三角面时简化（大文件简化可能要几十秒）。
4. 存进资源库的 `venues/`，设为当前工程的场馆（一步撤销）。场馆没有缩略图。

## 5. 渲染

`stage3d/ThreeStageRenderer.ts`，只用 three.js 本体和 addons（OrbitControls、TransformControls、加载器），没有用 React Three Fiber：每秒 30 帧的更新直接写实例缓冲，不经过 React 协调。

- 帧数据（`useStage3DFrame`）与 2D 舞台同一份预览求值：颜色来自 WASM 引擎的 `previewAt`，Pan / Tilt / 变焦与图案、棱镜、快门等光束通道来自 `buildSheet`，只为有这些通道的灯生成灯具表。
- 外形模板是程序生成的低面数几何体（`stage3d/shapes.ts`，每种 40~150 个三角面），按型号尺寸逐实例缩放。光轴沿 OFL“深”方向的外形（帕灯、泛光、成像灯、灯条、面板、频闪、观众灯、激光）把深度映射到本地 Y。
- 同一种几何体组（外形模板或同一个 GLB）的灯共用一组 `InstancedMesh`；摇头灯拆成底座、摇臂、灯头三组，每帧只改实例矩阵。发光面用实例颜色显示实际输出色，灯灭时显示暗灰。
- 光束角按变焦通道上标注的角度插值，其次按模型的最小 / 最大光束角，都没有时用外形的默认值；再乘上光圈（收到 15%）与雾化（加宽 40%）。
- 一个半球光加一个方向光，不开阴影。
- 只在新的一帧、相机移动、手柄拖动或尺寸变化时绘制。

### 5.1 光束

光束外观由 `stage3d/beamLook.ts` 从灯具表的通道值算出（纯函数，预览用的近似）：

| 通道 | 效果 |
|---|---|
| 快门 / 频闪 | 关光区间不出光；频闪区间按物理量（Hz）或区间内位置（1~20 Hz）方波闪烁，亮占 30%。相位按播放头时间算，暂停时画面不变 |
| 图案 | 当前值所在区间的图案（见 5.2）；开光区间没有图案 |
| 图案旋转 / 棱镜旋转 | 比例区间按物理量（rpm / Hz）或区间内位置（最快 0.5 转 / 秒）给转速，名称带 CCW / 逆 / reverse 的反向；角度 = 转速 × 播放头时间 |
| 棱镜 | 非开光区间即插入，面数取名称里的数字（3~16，默认 3），一束光分成 n 束，各偏开 5°，绕主光轴排开（最多 8 束） |
| 光圈 / 雾化 / 聚焦 | 光圈 0 为全开；雾化加宽并柔化边缘；聚焦偏离中间值时图案变模糊 |

画质档位（`stage3d/quality.ts`，偏好 `stage.beamQuality`）：

| 档位 | 画法 |
|---|---|
| 高 | 所有亮着的光束画体积光（每条视线 28 次采样） |
| 中 | 最亮的 32 束画体积光（14 次采样），其余画简单光锥 |
| 低 | 全部画简单光锥 |
| 自动（默认） | 播放时按 rAF 帧间隔调节：持续 2 秒超过 40 毫秒降一档，持续 5 秒低于 20 毫秒升一档 |

暂停或拖动播放头时按高一档画。

体积光（`stage3d/volumetric.ts`）：

1. 深度预渲染：不透明的场景（台面、布景、场馆、灯体）按半分辨率只写深度；光锥、光斑和选择圈在图层 1，不参与。
2. 每束光是一个封闭圆锥，只画背面。片元着色器在圆锥本地坐标（单位圆锥）里解析求视线的进入点，按场景深度截断，在区间内步进采样：图案（图集）、边缘柔化、离光源越远越淡、光束越窄越亮（按截面积），每个像素的起点错开以减少条纹。结果累加到半分辨率、半精度浮点的缓冲（不支持时退回 8 位）。
3. 合成：`1 - e^-x` 压缩后叠加到画面。

亮度乘烟雾浓度（`stage.haze`）。地面光斑按图案投射，简单光锥的亮度也随烟雾浓度变化。

### 5.2 图案（gobo）

- 内置 20 种程序生成的图案（`fixtures/lib/gobos.ts`）：dot、dots、ring、rings、star、stars、flower、rays、spiral、bars、grid、cross、triangle、square、honeycomb、breakup、waves、flame、moon、shatter。用带符号距离函数生成灰度遮罩，外圈裁成圆形光阑。
- 槽位没有指定图案时按名称的中英文关键词匹配（如“Star / 星” → star，“Spiral / 螺旋” → spiral），名称像“Open / 开光”的不投射，匹配不到的按槽位序号轮流取一个，相邻槽位看起来不同。
- 图集（`stage3d/goboAtlas.ts`）：一张 R8 纹理，8 × 4 格、每格 256 像素（2 MiB）。第 0 格是开光的圆形光阑；其余按需分配，用满时替换本帧没用到的格子。图案图片异步解码成灰度（亮度 × 不透明度）后写入。

### 5.3 布景、LED 屏与场馆

- 布景（`stage3d/scenery.ts`）：每个物件一个组，带轮廓线（选中时换成选中色）；多边形按顶点挤出，台阶由各级方块合并。背景图缩到最长边 2048 像素后铺在台面上，不透明度与 2D 舞台的偏好一致。
- LED 屏（`stage3d/screenFeeds.ts`）：视频素材取时间线上此刻播放这个素材的片段，直接用 `MediaPlayers` 为它渲染的 `<video data-clip-id>` 元素做 `VideoTexture`（与时间线同步，不另开解码器）；像素灯按型号的矩阵（列 × 行）取每个像素的预览色，每帧上传一张小的 `DataTexture`。没有内容时黑屏。
- 场馆（`stage3d/venue.ts`）：第一次用到时加载，所有网格共用一个顶点色材质；换模型或清除时立即释放。

## 6. 内存

| 措施 | 做法 |
|---|---|
| 按需加载 | 3D 舞台单独成包（`Stage3DView` 约 470 KB，three 公共部分约 260 KB），编辑器首屏不加载；切到别的视图时整个卸载 |
| 释放 | 卸载时释放全部几何体、材质和 WebGL 上下文（`forceContextLoss`）；导入的模型不再被任何灯使用时立即释放（`AssetMeshCache.retain`） |
| 共享几何体 | 同型号的灯共用一组实例网格，几何体只上传一次 |
| 不存贴图 | 规整后的 GLB 只有几何体和顶点色，资源库里没有纹理 |
| 面数上限 | 导入时超过 10 万三角面就简化；程序外形每种不到 150 个三角面；场馆模型上限 30 万三角面 |
| 绘制缓冲 | 设备像素比上限 1.5，绘制缓冲最多约 200 万像素（含 4 倍多重采样约 70 MB） |
| 体积光 | 半分辨率的深度缓冲与半精度颜色缓冲，第一次画体积光时创建，200 万像素的画面下约 6 MB；低档不创建 |
| 图案 | 一张 2 MiB 的单通道图集，最多同时 31 种图案 |
| LED 屏 | 视频直接用页面里已有的 `<video>` 元素，不另外解码；像素灯的贴图只有列 × 行个像素 |
| 资源列表 | 前端只存资源元数据，文件经 asset 协议按需加载；图标列表用 `loading="lazy"` |

估算（中等规模：300 台灯、20 个型号）：

- 程序外形：几何体每种约 16 KB；实例矩阵约 300 × 4 组 × 64 B ≈ 77 KB；光锥与光斑实例约 50 KB。
- 20 个型号都用到上限 10 万三角面的 GLB 时：带索引的几何体每个约 3 MB，合计约 60 MB。
- 绘制缓冲：常见的 1000 × 600 预览区在 1.5 倍像素比下约 135 万像素，含多重采样约 45 MB。

- 场馆模型到上限 30 万三角面时，合并后的几何体（位置、法线、顶点色 + 32 位索引）约 9~12 MB。

以上是按数据结构计算的估算，没有在核显机器上实测，体积光的帧时间也没有实测。实测可以打开 3D 舞台的“统计”核对几何体与纹理数，配合任务管理器的“GPU 专用内存 / 共享内存”观察。

## 7. 目前的限制

- 文字物件在 3D 里不画；多边形顶点只能在 2D 舞台里拖动。
- 图案只投射到光束和台面 / 地面的光斑上，不投射到布景、LED 屏或场馆模型上；不画阴影。
- 光束效果是预览用的近似：频闪、旋转速度、光圈 / 雾化 / 聚焦的换算与实灯不一定一致。
- 导入时丢掉贴图，只保留材质颜色（场馆模型同样）；Draco 压缩的 glTF 不支持。
- 关节只认 Pan 轴过原点（模型左右居中）的摇头灯。
